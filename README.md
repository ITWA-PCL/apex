# 🏢 Department Application Starter Kit (ฉบับคู่มือพนักงาน)

เทมเพลตมาตรฐานสำหรับการพัฒนา Application ภายในองค์กร ออกแบบมาเพื่อให้แต่ละแผนกสามารถพัฒนาขั้นตอนการทำงาน (Business Workflow) ได้อย่างอิสระด้วย AI โดยยังคงมาตรฐานความปลอดภัยระดับสากล (ISO 27001 / CIA Triad)

---

## 🧭 กฎเหล็กในการทำงานร่วมกัน (Code of Conduct)

1. **เขียนโค้ดเฉพาะในโฟลเดอร์ `app/` เท่านั้น:**  
   พื้นที่นอกโฟลเดอร์นี้ (เช่น `auth-proxy/`, `.github/`, `docker-compose.yml`) เป็นระบบความปลอดภัยส่วนกลางที่ IT ดูแล ห้ามแก้ไขโดยเด็ดขาด
2. **ไม่ต้องสร้างระบบ Login เอง:**  
   ระบบส่วนกลางมี Security Gateway คอยดึงตัวตนจากระบบบริษัทส่งมาให้ผ่าน HTTP Header อยู่แล้ว
3. **ห้ามบันทึกรหัสผ่านลงในโค้ด (Zero Hardcoded Secrets):**  
   ห้ามใส่ Password, Token, หรือ Private Key ลงในไฟล์โค้ดเด็ดขาด หากจำเป็นต้องใช้ให้แจ้งทีม IT
4. **ห้าม Push ตรงเข้ากิ่ง `main`:**  
   การนำระบบขึ้นใช้งานจริง ต้องส่งผ่านระบบ **Pull Request (PR)** เพื่อให้ IT ตรวจสอบความปลอดภัยก่อนเสมอ

## 🚀 ขั้นตอนการเริ่มทำงาน (Step-by-Step)

### ขั้นตอนที่ 1: แตกกิ่งงานใหม่ (ห้ามทำบนกิ่ง main)
เปิด Terminal หรือโปรแกรม Git แล้วสร้าง Branch ประจำฟีเจอร์ของคุณ:
bash
git checkout -b feature/ชื่อฟีเจอร์-หรือชื่อแผนก
# ตัวอย่าง: git checkout -b feature/leave-request-form

### ขั้นตอนที่ 2: เริ่มต้นรันระบบบนเครื่องตัวเอง
เปิดโปรแกรม Docker Desktop ให้พร้อมทำงาน จากนั้นรันคำสั่ง:

Bash
docker compose up --build
เมื่อคำสั่งทำงานเสร็จสิ้น ให้เปิดเบราว์เซอร์ไปที่:

👉 http://localhost:8080

(คุณจะเห็นหน้าจอเริ่มต้นพร้อมข้อมูลจำลองของพนักงาน)

### ขั้นตอนที่ 3: สั่ง AI พัฒนาแอปตามต้องการ
เมื่อใช้ AI (เช่น ChatGPT, Claude, Cursor) ช่วยเขียนระบบ ให้ใช้ข้อความกำกับ (Prompt) เสมอว่า:

ตัวอย่าง Prompt สำหรับสั่ง AI:

"ระบบนี้มี IT Gateway จัดการเรื่อง Login ให้แล้ว ไม่ต้องเขียนหน้า Login หรือสร้างตารางเก็บ Password ให้ดึงรหัสพนักงานและสิทธิ์จาก Header X-User-ID, X-User-Email, X-User-Role และ X-User-Department ได้เลย"

### ขั้นตอนที่ 4: ตรวจสอบฐานข้อมูลประจำแผนก
ระบบนี้มีฐานข้อมูล PostgreSQL แยกอิสระสำหรับแผนกของคุณ ค่าเชื่อมต่อเบื้องต้น:

Host: dept-db (เมื่อเรียกจากใน Container) หรือ localhost

Database Name: dept_db

Username: dept_user

Password: dept_password_local

## 📤 ขั้นตอนการส่งงานให้ IT ตรวจสอบ (Submit PR)
เมื่อพัฒนาและทดสอบระบบบนเครื่องตัวเองเรียบร้อยแล้ว ให้ทำตามขั้นตอนนี้เพื่อส่งระบบขึ้นเซิร์ฟเวอร์จริง:

### 1.บันทึกการแก้ไข (Commit):

Bash
git add app/
git commit -m "feat: เพิ่มระบบขออนุมัติเอกสารแผนกจัดซื้อ"

### 2.ส่งงานขึ้นเซิร์ฟเวอร์กลาง (Push):

Bash
git push origin feature/ชื่อฟีเจอร์-หรือชื่อแผนก
### 3.เปิด Pull Request (PR):

เข้าไปที่หน้าเว็บ Repository บน GitHub

คลิกปุ่มสีเขียว "Compare & pull request"

กรอกรายละเอียดว่าฟังก์ชันนี้ทำอะไร และมีใครใช้งานบ้าง

กด "Create pull request"

### 4.รอระบบสแกนความปลอดภัย:

ระบบอัตโนมัติจะสแกนหา Secret หลุด และตรวจช่องโหว่ความปลอดภัย

หากขึ้นเครื่องหมายถูกสีเขียว (Passed) ทั้งหมด ทีม IT จะเข้ามา Review และกด Approve นำขึ้นระบบจริงของบริษัทให้ทันที
